# От постановки задачи до передачи на ревью

1. Зафиксируй наблюдаемый результат для пользователя. Укажи исходную ревизию, область изменений, зависимости и открытые решения. Если изменение состоит из нескольких шагов, выдели первый шаг, который можно проверить независимо.
2. Назови проверку приёмки до реализации. Если два человека делят устройство, стенд или набор изменяемых данных, договорись, кто ими владеет в этот момент.
3. В отчёте укажи ревизию результата, изменённое поведение, выполненную проверку и её наблюдаемый результат. Отдельно запиши пропущенную проверку и конкретную причину.
4. Передай следующему участнику один проверяемый вопрос. Например, для исправления очистки фильтра попроси проверить путь «ввести запрос → очистить → увидеть полный список» на переданной ревизии.

Источник адаптации — локальные процедуры постановки задач и передачи результатов в Knowledge. Работает с текстовым issue, GitHub Projects или локальным трекером.
